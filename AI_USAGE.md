# Использование AI

## Инструмент

В разработке использовался OpenAI Codex как coding agent с доступом к файлам репозитория. Агент анализировал существующую архитектуру, создавал и изменял C#-файлы, проверял diff и журнал компиляции Unity. Git-коммиты, Unity-сцены, префабы и ScriptableObject-ассеты агент не создавал и не изменял.

## Задачи, переданные AI

- анализ технического задания и составление плана;
- реализация конфигурации фабрики;
- экономика машин и интеграция с существующим `ValueSystem`;
- активное и offline-производство, Boost и mobile lifecycle;
- сохранение прогресса через существующий `GameSaver`;
- UI-компоненты для машин, производства, Boost, offline-дохода и IAP;
- интеграция Unity IAP v5 через абстракцию;
- защита consumable-награды от повторной выдачи;
- многопровайдерная архитектура аналитики и Console provider;
- четыре Edit Mode unit-теста;
- подготовка README и документации об использовании AI.

## Примеры ключевых промптов

- «Найди файлы конфигурации агента и кодстайла, прочитай и исполняй, что там написано».
- «Не собирай dotnet сборки и не трогай префабы и сцены в проекте».
- «Используй ScriptableObject, но сами объекты физически не создавай».
- «Через ID валюты, строка, больше от ValueSystem ничего не нужно».
- «Добавил GameSaver, можно с ним работать как с синглтоном».

## Что реализовано с помощью AI

AI подготовил основную gameplay-логику фабрики, интерфейсы интеграций, адаптер сохранения, IAP-сервис, аналитику, UI-скрипты, тесты и документацию. Для Unity IAP v5 агент сверял актуальный API с официальной документацией Unity и добавил пакет `com.unity.purchasing` версии `5.0.4`.

## Что сделано вручную

Разработчик самостоятельно:

- создал и настроил ScriptableObject-ассеты;
- добавил компоненты на объекты сцены;
- связал сериализованные поля UI;
- настроил `ValuesInstaller` в `ProjectContext`;
- добавил и настроил `GameSaver`;
- собрал экран фабрики;
- проверил gameplay и покупки через Fake Store;
- запустил Edit Mode тесты и подтвердил успешное прохождение всех четырёх тестов.

## Изменённые или отклонённые предложения AI

Первоначально AI предложил JSON-конфигурацию. Решение было заменено на `FactoryConfigurationAsset`, чтобы конфигурация соответствовала принятому в проекте подходу с ScriptableObject.

Первоначальная версия экономики содержала отдельный баланс фабрики. Решение было отклонено: итоговая реализация использует существующий `IValueSystem` и строковый ID валюты.

AI также пытался зарегистрировать `ValueSystem` внутри `FactoryInstaller`. Это было удалено, поскольку у системы уже есть собственный `ValuesInstaller` в `ProjectContext`.

## Обнаруженные ошибки и спорные решения

- первоначально не была учтена обязательная интеграция с существующим `ValueSystem`;
- граница ответственности между `FactoryInstaller` и `ValuesInstaller` была выбрана неверно и затем исправлена;
- ранняя версия интеграции сохранения ожидала отсутствующий API `GlobalValuesSave`, после чего `ValuesInstaller` был адаптирован к фактическому `GameSaver`;
- после добавления `GameSaver` тип сохранения не соответствовал generic-ограничению `SaveGameBase`; структура была приведена к ожидаемой модели;
- в Unity IAP v5 сначала использовалось неверное имя свойства транзакции `TransactionId`; после проверки API оно было заменено на `TransactionID`;
- итоговые сцены, префабы, конфигурационные ассеты и сериализованные ссылки проверялись и настраивались разработчиком вручную.

Разработчик просматривал результат после каждого этапа, корректировал архитектурные решения и подтвердил работу gameplay, UI, IAP, аналитики и unit-тестов.
